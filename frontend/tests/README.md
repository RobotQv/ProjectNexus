# 前端自测脚本（可选）

课程不要求单独提交自测产物。这两个脚本的作用是：把开题报告 6.1「依赖原型与交互验收」
的五条场景变成可重复执行的检查，改完页面能立刻知道有没有跑偏，也方便测试负责人复核。

不是 npm 测试，不需要 Node。它们用 Python 里的 JS 引擎**真实执行**前端的 JavaScript：

- `原型交互自测.py` — 用 Duktape（dukpy）跑 `prototype/项目交互原型.html` 里的脚本。
  不是只调函数，而是用真实的 DOM 事件委托和假定时器驱动点击与轮询，
  所以「点通过会不会重复建任务」「离开页面会不会停轮询」这类行为是真被验证的。
- `工程逻辑自测.py` — 用 QuickJS 跑 `web/src/demo/` 下的演示后端与依赖规则，
  覆盖 Vue 工程里 6.1 五条验收的实现，外加 start / finish 关卡的边界用例。

## 运行

```bash
pip install dukpy quickjs
python frontend/tests/原型交互自测.py
python frontend/tests/工程逻辑自测.py
```

两条命令都以 `RESULT: PASS` 结尾表示全通过。当前分别是 63 项与 36 项。

## 它们覆盖了什么

| 6.1 交互场景 | 检查内容 |
| --- | --- |
| 新增资料 | 202 排队 → 处理中 → 解析就绪 → 索引就绪；解析与索引分开判定；失败分支给出原因与重试；**离开页面停止轮询** |
| 资料问答 | answered 带事实与来源；clarify 给候选且不编造事实；insufficient 明确说明 |
| 建议确认 | 编辑字段后确认写入正式任务；**重复点击返回同一 target_id 且不重复建任务**；驳回不建任务 |
| 依赖比较 | A=70 / B=80，关卡 90 →「尚未到关卡」，关卡 80 →「当前关卡受阻」 |
| 缺失日期 | 清空人工预计完成 →「时间信息不足」，**不判为低风险** |

另外覆盖了新增任务里的 AI 助理链路：草稿阶段不写正式任务 → 提交进入 pending
→ 正式审核通过后才创建任务，以及未识别字段留空而不编造。

## 说明

这两个脚本验证的是**前端自身**的逻辑与交互。真实接口联调（登录、分页、409 版本冲突、
Worker 轮询、建议审核写库）仍需按 `../web/README.md` 启动本机后端后手工走查，
后端契约以 `/openapi.json` 为准。
